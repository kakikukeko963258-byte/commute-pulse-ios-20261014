# プライバシー

## 位置情報の扱い

CommutePulse の位置情報機能は、実際の位置を端末上で処理する設計を前提とします。実際の位置を外部サービスへ送信・保存する仕組みを追加する場合は、この文書とアプリ内の説明を先に更新し、送信先、目的、保持期間、利用者が無効化・削除する方法を明記してください。

位置情報の権限は必要な目的とタイミングをアプリ内で説明し、許可がない場合も利用者が状態を理解できるようにします。権限を拒否された場合に、位置情報が取得できたかのような表示をしてはいけません。

デバッグ用シミュレーションは実際の位置情報と明確に区別します。シミュレーションのデータを実測値として扱ったり、実際の出発・到着として記録したりしないことを確認してください。

## 共有とログ

- 位置情報、通勤経路、駅候補などをログ、クラッシュ報告、解析サービスへ含めないでください。必要な診断では、座標ではなく権限状態や処理結果など最小限の情報を使います。
- App Group の共有コンテナを使う場合、共有するデータ項目と目的を限定し、不要になった状態データを消去できるようにします。
- Widget と Live Activity には、画面ロック中に表示されても差し支えない情報だけを載せます。
- GitHub Actions Artifact にはアプリのビルド成果物だけを含め、秘密情報、ユーザーの位置・通勤データ、ローカル設定を含めません。
- 署名用秘密情報を CI で使う構成にする場合、リポジトリへ直接保存せず、必要最小限の GitHub Secrets として管理し、ログへ値を出力しません。

## リリース前の確認

本書の内容は設計上のプライバシー要件です。実装が実際にこの要件を満たしているか、コード、権限宣言、依存 SDK、通信先、ログを確認した結果はまだありません。リリース前にそれらを点検し、意図しない通信や位置情報の保存がないことを確認してから、実際の動作に合わせて本書とアプリ内のプライバシー説明を更新します。
